# AI Messenger

Корпоративный мессенджер с встроенным AI-ассистентом. Написан на React + Express + PostgreSQL, общение в реальном времени через Socket.io, звонки через WebRTC.

## Что умеет

- **Чаты** — личные и групповые, с поддержкой текста, картинок, видео, голосовых сообщений и файлов
- **Реалтайм** — сообщения, статусы «печатает...», прочитанные сообщения, онлайн-статусы — всё обновляется мгновенно
- **Звонки** — голосовые и видеозвонки прямо в браузере (WebRTC, peer-to-peer)
- **AI-ассистент** — встроенный чат с локальной LLM (Ollama, модель llama3.2), умеет отвечать с учётом загруженной базы знаний
- **Реакции** — эмодзи-реакции на сообщения
- **Редактирование и удаление** сообщений
- **Поиск** по сообщениям в чатах
- **Админка** — управление пользователями, статистика, загрузка документов в базу знаний AI
- **Аватарки и профили** — кастомизация профиля, загрузка аватарок

## Быстрый старт

### 1. Поднимаем базу и AI

```bash
docker-compose up -d
```

Это запустит PostgreSQL (порт 5432) и Ollama (порт 11434).

### 2. Настраиваем переменные окружения

```bash
cp .env.example .env
```

Основные переменные:

```
DATABASE_URL=postgresql://user:password@localhost:5432/ai_messenger
JWT_SECRET=ваш-секретный-ключ
JWT_REFRESH_SECRET=ещё-один-секретный-ключ
OLLAMA_URL=http://localhost:11434
OLLAMA_MODEL=llama3.2
```

### 3. Устанавливаем зависимости и готовим базу

```bash
npm install
npm run db:migrate
npm run db:seed
```

Seed создаст аккаунт администратора: `admin@messenger.local` / `admin`

### 4. Запускаем

```bash
npm run dev
```

Клиент откроется на `http://localhost:5173`, сервер — на порту `3001`.

## Как это работает

**Аутентификация** — JWT с access/refresh токенами. Access живёт 15 минут, refresh — 7 дней. Регистрации нет, пользователей создаёт админ.

**Сообщения** — REST API для CRUD-операций + Socket.io для мгновенной доставки. Поддерживаются типы: текст, картинки, видео, голосовые, видеокружочки, файлы.

**Звонки** — сигналинг через Socket.io, медиа напрямую между браузерами через WebRTC. Используются STUN-серверы Google для прохода через NAT.

**AI-ассистент** — запросы к локальному Ollama. Перед ответом ищет релевантные документы в базе знаний и подставляет их в контекст. Документы загружает админ через админку.
